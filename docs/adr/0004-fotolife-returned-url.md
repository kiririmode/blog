# エントリにはフォトライフが返す画像 URL をそのまま書く

スクリプトは、フォトライフのAPIが返す`hatena:imageurl`を、そのまま本文に書く。ADR-0003で決めた、拡張子の前に`_original`を付けた元の大きさのURLを書く方式はやめる。2026-11-23にユーザーがこう決めた。

`_original`版のURLは、いつも存在するわけではない。はてなのヘルプによれば、オリジナルサイズの画像は、アカウントの設定「オリジナルサイズの画像を保存」をオンにすると保存される（<https://hatena.zendesk.com/hc/ja/articles/19318604630937>）。2026-11-23に、APIで上げた横幅360pxの図2枚では、`_original`版のURLが403を返した。フォトライフが返したURLは200を返し、図を元の大きさで表示した（issue #342）。

画像の表示の横幅は、フォトライフのアカウントの設定で決まる。2026-11-23に、ユーザーがこの設定を450pxから900pxに変えた。そのあとAPIで上げた1600×200のPNGでは、フォトライフが返したURLは900×113の画像を返し、`_original`版のURLは1600×200の画像を返した。どちらのURLもHTTPの200を返した。

## Consequences

表示の横幅（2026-11-23の時点で900px）より広い画像は、その横幅に縮小されて載る。`_original`版でないURLを弾く、コミット前とCIの検査はなくした。公開済みエントリにある`_original`版のURLは書き換えない。
