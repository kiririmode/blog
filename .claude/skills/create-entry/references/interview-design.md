# インタビューの設計

`/grilling` でテーマを深掘りする際の進め方を定める。問いの軸は固定せず、エントリごとに提案する。固定の軸で問うと、どのエントリも同じ構成に収束するためである。

## 1. 固定の2問

最初に次の2問を一問ずつ聞く。どちらも推奨回答を添える。

- **核心**: この記事で一番言いたいことは何か（一文で言うと？）
- **出発点**: 個人的な体験・もやもやから始まるのか、外部の情報・構造分析から始まるのか

「出発点」のやり取りの中で、`contents-guideline.md` の「記事のモード」表に照らしてエッセイ型か分析型かの判断を提示し、ユーザーに確認する。ここでモードを確定する。以降のステップでモードを改めて提案することはしない。

## 2. 軸の提案と確定

核心とモードを入力に、このエントリ固有の軸を3〜5個、一括で提示する。各軸には「このエントリになぜこの軸が要るか」を一行添える。ユーザーが追加・削除・修正し、確定させる。

モードによって有効な軸は変わる。エッセイ型なら体験の転換点や感情の揺れ、分析型なら比較対象や前提条件のように、モードに沿った軸を選ぶ。

## 3. 軸ごとの深掘りとbrain参照

軸が確定したら、`brain-lookup.md` の手順でbrainの候補ノートをプリフェッチする。その後、軸を一問ずつ問う。各問いには推奨回答を添え、ユーザーの回答を待つ。

brainの材料は、ユーザーが回答した後に提示する。推奨回答にはbrainの内容を混ぜない。ユーザーが自分の考えを言う前にbrainの論調へ誘導されること（アンカリング）を避けるためである。

再定式化の提案が採用されて核心または着地点が変わった場合は、影響を受ける軸だけを差し替える・追加する。回答済みの軸と内容は維持する。この軸の再提案はインタビュー全体で1回までとする。

## 4. 収束の条件

次の3条件をすべて満たした時点でインタビューを終了し、ステップ3に進む。

- 確定した全軸について、ユーザーとAIの間で認識の齟齬がない
- 提示したbrainの提案すべてについて、採用・不採用が決まっている
- インタビュー結論の要約をユーザーが確認した。要約には、核心、モード、各軸の結論、採用した材料（種類・変化の一文・原典の出典情報）を含める
