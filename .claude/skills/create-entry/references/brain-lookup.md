# brainの参照

インタビュー（`interview-design.md` の3）で、brainリポジトリ（`~/src/github.com/kiririmode/brain`）の知見を使い、エントリを深める提案を出すための手順を定める。brainは読み取り専用とし、ファイルを作成・変更しない。

## 提案の種類と参照範囲

提案は4種類ある。補強・接続・再定式化を主とし、反証は従とする。

| 種類 | 内容 | 参照範囲 |
| --- | --- | --- |
| 補強 | 主張を裏付ける外部資料の知見・データ・事例 | `20_literature_notes`, `10_sources` |
| 接続 | ユーザー自身の過去の主張とテーマを結び、新しい切り口を出す | `30_permanent_notes`, `40_structure_notes` |
| 再定式化 | brainの概念を使い、核心を一段抽象化・具体化する | `30_permanent_notes`, `40_structure_notes` |
| 反証（従） | 主張と緊張関係にある知見。主張を崩しうる強い材料に限る | 上記の範囲すべて |

`00_inbox`、`90_archive`、`templates` は参照しない。

## プリフェッチ

軸が確定した直後に、Exploreサブエージェントを1つ起動する。サブエージェントには、核心、モード、確定した軸の一覧を渡す。サブエージェントは軸ごとに候補ノートを集め、軸ごとに「パス・タイトル・要点一行・該当しうる提案の種類」の一覧を返す。

検索には `qmd` を使う。インデックスはbrainリポジトリ内にあるため、brainのルートで実行する。

```bash
cd ~/src/github.com/kiririmode/brain
qmd query $'intent: <軸で知りたいこと>\nlex: <キーワード>\nvec: <言い換えた問い>' -c zettelkasten --min-score 0.1 --all --no-rerank
qmd get <docidまたはqmd://パス> --full-path   # 実ファイルパスを得る
```

qmdのパスは `30-permanent-notes` のようにハイフン区切りになる。実ディレクトリは `30_permanent_notes` である。ファイルを開くときは `qmd get --full-path` の結果を使う。

## 回答後の判定と提示

ユーザーが軸に回答したら、メインの会話がその軸の候補を回答内容で絞り込む。候補が回答の論点とずれている場合だけ、回答の言葉で追加の `qmd query` を実行する。

候補ごとに「採用すると、エントリのどこがどう変わるか」を一文で書く。一文が書けた材料だけを提案する。一文の型は種類ごとに決まっている。

- 補強: 「主張Xに、現状は無い根拠（データ・事例・研究）が付く」
- 接続: 「過去の主張Yとつながり、論に○○という視点が加わる」
- 再定式化: 「核心または着地点が○○に変わる」
- 反証: 「反例・限界として○○が加わる」

すでに根拠がある主張に重ねるだけの材料と、主張から外れた周辺知識は、一文が書けないものとして扱う。提案するときは、この一文を冒頭に置き、続けてノートのタイトルと要点を示す。その軸で一文が書ける材料がなければ、「brainに有効な材料なし」と一行だけ書く。

## 出典の扱い

brainはprivateリポジトリである。ブログ本文には、brainのノートのパスやリンクを書かない。

補強の材料は原典を引用する。文献ノートのfront matterの `source:` は `10_sources` のノートへのwikiリンクであり、そのソースノートの `source:` に原典のURLがある。書籍などURLが無い場合は書誌情報を使う。原典まで辿れない材料は補強に使わない。

接続・再定式化で使ったpermanent noteの主張は、ユーザー自身の考えとして地の文で書く。出典は付けない。

採用した材料の原典の出典情報は、インタビュー結論の要約の時点で確定させておく。
