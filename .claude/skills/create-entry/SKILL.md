# Create-Entry Skill

このSKILLは、読者が惹きつけられる、魅力的なブログエントリを作成するためのもの。

# Instructions

ブログエントリを作成するには、以下のステップを実行する。

1. 新規エントリの作成: 以下のコマンドで新しい下書きエントリのファイルを作成する。
   ファイルは `kiririmode.hatenablog.jp/entry/_draft/` に数字のファイル名（はてなブログのエントリID）で作成される。コマンドの出力がそのパスである。

   ```bash
   npm run entry
   ```

2. インタビューによるテーマの深掘り:
   `/grilling` を起動し、`references/interview-design.md` に従ってテーマを深掘りする。固定の2問（核心・出発点）でモードを確定し、エントリ固有の軸を提案・確定してから、軸ごとに一問一答で進める。各軸への回答後には、`references/brain-lookup.md` に従ってbrainリポジトリの知見からエントリを深める提案を出す。

   エッセイ型に確定した場合は `references/essay-mode-example.md` の模範例を通読し、リズム・口語表現・呼びかけ方を把握しておく。

   `references/interview-design.md` の収束の条件をすべて満たした時点でインタビューを終了する。

3. ブログエントリの構造を作成する:
   ステップ2で確定したモードとインタビューの結論（各軸の合意内容と採用したbrainの材料）を踏まえて、下書きエントリの構成案を作る。Plan Agentは使わず、インタビューの文脈を持つこの会話で作成する。
   構成案は、見出しの構成と、採用したbrainの材料をどの節に置くかをユーザーに示し、承認を得てからステップ4に進む。

   構造は次のとおりとすること。
   1. **導入部**: 課題提起から入り、背景説明、解決策の概要を提示
   2. **目次**: `[:contents]` ディレクティブを挿入
   3. **本文**:
      - `#` を大きなセクションに、`##` をサブセクションに、`###` は必要な場合のみ使用
   4. **最後に**: まとめを記述する
   テンポ・ウィットの方針は `references/voice-examples.md` を参照すること。

4. タイトルを決める:
   タイトルガイドライン `references/title-guideline.md` に従ってタイトルを検討し、下書きエントリのFront Matter部に記載すること。

5. 文体を鑑みて、エントリのBODYを記述する
   コンテンツガイドライン `references/contents-guideline.md` に従って記述する。

6. テンポ・ウィットチェックを行う
   書いたBODYを通読し、`references/voice-examples.md` の避けるべきパターン表・テクニック集に該当する箇所がないか確認する。問題があれば書き直す。エッセイ型の場合は、テクニック7〜9（口語化・二人称呼びかけ・問いかけリズム）も確認する。

7. yomiyasuによる推敲:
   `/yomiyasu` を呼び出し、下書きエントリファイルを推敲する。最終稿は下書きエントリファイルを直接更新させる（原文のファイルを更新する依頼として渡す）。文書の種類は、エッセイ型なら `essay`、分析型なら `article` を指定する。資料（`--material`）は渡さない。

   ```text
   /yomiyasu kiririmode.hatenablog.jp/entry/_draft/<file>.md を推敲し、このファイルを直接更新してください。文書の種類は essay（分析型なら article）です。
   ```

   yomiyasuの手順（lint・diff・verifyの検査を含む）を1回実行したら完了とし、診断と修正を繰り返すループは行わない。yomiyasuの最終稿をそのまま採用し、このステップ以降は本文を書き換えない。AI臭さを除く工程を最後に置くためである。

   検査記録等の中間ファイルは作業用のみとし、コミット対象には含めない。

   このSKILLは textlint（`npm run lint`）は実行しない。

8. 下書きエントリファイルのFrontMatterにおけるDateフィールドを、現在時刻（JST）に置き換える
9. 変更をコミットする

    ```bash
    /commit
    ```
